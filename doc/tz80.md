# tz80 — 単一命令ステップ Z80 デバッガ(cpmsim 互換)

## 目的

tizix のフレークな **ワイルドジャンプ crash**(PC/リターンアドレスが破壊され
未定義命令 `Op-code trap` へ飛ぶ。FatFs 操作の最中/直後、タイマ ISR がらみ、
毎回別番地、ベースコミットから ~2.5%)を捕まえるための決定論的デバッガ。

cpmsim(z80pack)は「実行しっぱなし」で、ISR がどの命令で入るかを制御できず、
crash の瞬間の状態も取れない。tz80 は:

- **1 プロセス実行 = 1 命令**。状態はファイルに永続化。繰り返し呼ぶたび 1 命令進む。
- **タイマ割り込みを手動注入**できる(`tz80 int`)。「この命令の直後に ISR を
  入れる」を狙い撃ちできる → プリエンプト起因の破壊を再現。
- 毎ステップ **メモリ全域をファイルに書き出す**。ステップ間で diff / 監視できる。
- **レジスタファイル**(人間可読・編集可)から実行開始できる → 状態のショートカット。
- **ウォッチポイント**(指定領域への書込み、SP 範囲外、PC 想定外)で破壊の瞬間に停止。

## アーキテクチャ

```
  python z80 モジュール(命令デコード/実行の核。runcmd.py が既に使用)
        │
  tz80.py ── cpmsim デバイス再現(コンソール port 0/1、FDC port 10-16、
        │                          タイマ port 27 + IM1 @ 0x0038)
        │   ── ディスクイメージ (arch/z80pack/disks/drivea.dsk, driveb.dsk)
        │   ── 永続状態 (python/tz80_state/)
        ▼
  ssh コンソール表示 + ファイル出力
```

依存: `z80`(Ivan Kosarev、`pip install z80`)。**rocky9 では `python3.11` でのみ動く**
(`python3`=3.9 は `str | None` 型ヒントで import 不可)。tz80 は shebang / 実行を
`python3.11` にする。

状態確認済み(2026-08-30): `reset` → `run --quiet --max 400000` で tizix が
`FAT Drive DETECTED / System Driver LOADED / #` プロンプトまでブート(~1.5 秒)。
FDC / コンソール / タイマ IM1 割込 / save-load / 全機能動作。

## 永続状態 — `python/tz80_state/`

| ファイル | 内容 |
|---|---|
| `regs.txt` | レジスタファイル。`NAME=HEX` 1 行ずつ。**人間が編集可**。次ステップはこの値から。 |
| `mem.bin`  | メモリ全域 64KB の生バイナリ。毎ステップ上書き。 |
| `io.json`  | デバイス状態(FDC レジスタ、タイマ蓄積サイクル、割込ペンディング、コンソール入力キュー)。 |
| `trace.log`| 実行した命令の 1 行履歴(addr / opcode / 逆アセンブル / T-state / tick / ISR マーク)。追記。 |
| `screen.log`| **画面表示 + 全レジスタ**のブロックを `==================================================` 区切りで蓄積。`step`/`step N` は毎ステップ、`run` は停止点。`reset`/`screen clear` で消去。`screen [N]` で末尾 N ブロック表示。 |
| `console.out` | Z80 が `out (1)` した文字の蓄積(ssh 表示と同じ内容)。 |
| `watch.txt` | ウォッチポイント定義(下記)。人間が編集可。 |
| `snap/<name>/` | 名前付きスナップショット(regs.txt / mem.bin / io.json のコピー)。 |

### `regs.txt` の書式

```
PC=0100
SP=8FFE
AF=0044
BC=0000
DE=0000
HL=8400
IX=0000
IY=A000
AF_=0000       # 裏レジスタ(AF')
BC_=0000
DE_=0000
HL_=0000
I=00
R=00
IFF1=1
IFF2=1
IM=1
HALTED=0
# --- メタ(実行制御。レジスタではない) ---
CYCLES=0       # 総 T-state 数
TICKS=0        # 100Hz タイマ割込の回数
INT_PENDING=0  # 1 なら次ステップ冒頭で ISR を実行
TIMER_AUTO=1   # 1: サイクル蓄積で自動的に INT_PENDING を立てる / 0: 手動のみ
DRIVE=0        # FDC 選択ドライブ(0=drivea, 1=driveb)。out (10) で更新
```

`#` 以降はコメント。未知の行は無視。編集して `tz80 step` すればその状態から実行。

## コマンド (CLI)

```
python python/tz80.py <cmd> [args]
```

| cmd | 動作 |
|---|---|
| `reset` | コールドブート。drivea.dsk セクタ 0(128B)を 0x0000 へ、PC=0、全レジスタ 0、IFF=0、IM=0、CYCLES=0。io.json/console.out/trace.log 初期化。 |
| `step` / (引数なし) | 1 命令実行。`INT_PENDING` が立っていれば冒頭で ISR。実行後、regs.txt / mem.bin / io.json / trace.log を更新し、逆アセンブル + レジスタを表示。 |
| `step N` | N 命令。各命令ごとに trace.log へ。表示は最後の状態 + 途中で watch/trap 停止したらそこまで。 |
| `run [--max N] [--until 0xADDR] [--nowatch] [--quiet]` | watch / `--until` PC 到達 / `--max`(既定 300万)まで自走。`--quiet` は毎命令の trace/逆アセンブルを省いて高速(~270k step/s。長距離を一気に走る用)。停止点だけ trace に残る。 |
| `int` | `INT_PENDING=1`。次ステップ冒頭で IM1 割込(push PC / PC=0x0038 / IFF1=IFF2=0)。手動 ISR 注入。 |
| `int auto on\|off` | `TIMER_AUTO` 切替。off にすると自動プリエンプト無し = 純粋な単一フロー。 |
| `regs` | regs.txt を整形表示(フラグ分解、次命令の逆アセンブルも)。 |
| `setreg NAME 0xVAL` | regs.txt の 1 項目を書換え(手編集の代わり)。 |
| `mem 0xADDR [LEN]` | メモリ region を hex+ASCII ダンプ(既定 LEN=128)。 |
| `dis 0xADDR [N]` | 指定番地から N 命令逆アセンブル(既定 N=16)。 |
| `stack [N]` | SP から N ワード(既定 16)を表示(リターンアドレス追跡用)。 |
| `save <name>` | 現状態を `snap/<name>/` へ。 |
| `load <name>` | `snap/<name>/` から復元(regs/mem/io)。 |
| `snaps` | スナップショット一覧。 |
| `watch add <spec>` / `watch del <n>` / `watch list` | ウォッチポイント編集(`watch.txt` 相当)。 |
| `console in <text>` | コンソール入力キューに文字列を積む(`in (0)` が rx-ready、`in (1)` が 1 文字返す)。シェルからのコマンド投入に使う。 |
| `trace [N]` | trace.log の末尾 N 行。 |
| `screen [N]` / `screen clear` | screen.log の末尾 N ブロック表示 / 消去。 |

## ウォッチポイント — `watch.txt`

1 行 1 スペック。命令実行後に評価し、真なら `run`/`step N` を停止。

```
mem 8400 8500 w      # 0x8400-0x84FF への書込みがあったら停止(スケジューラ PCB/wait-wake)
mem 8419 85EE w      # VFS/pipe/kdir データ帯への書込み
sp < 8C00            # SP が下がりすぎ(block0 スタックオーバーフロー疑い)
sp > 9000            # SP が上がりすぎ(スタック破壊)
pc-range            # PC が「正常コード域」外に出たら停止:
                    #   [0x0100,0x8000) カーネル / [0x9000,0xA000) DRIVER /
                    #   [0xA000,0xE000) プロセス枠  以外はワイルドジャンプ
opcode-illegal      # z80 モジュールが未定義/トラップ扱いする命令に当たったら停止
halt-with-di        # HALT 実行時に IFF1=0 なら停止(cpmsim の "INT disabled and HALT")
```

`w` = write, `r` = read, `rw` = both。`mem LO HI` は半開区間。

## デバイス再現(cpmsim 互換)

### コンソール

| ポート | 方向 | 動作 |
|---|---|---|
| 0 | in  | ステータス。入力キューに文字あり → 非0(cpmsim は 0xFF)、無ければ 0。 |
| 1 | in  | 入力キューから 1 文字(なければ 0)。 |
| 1 | out | 文字を `console.out` へ追記 & ssh(stdout)へ。CR 変換はしない(生)。 |

### FDC(ディスク)

cpmsim フロッピー幾何: 77 track × 26 sector × 128B。`arch/z80pack/mkfatdisk.sh` /
`diskio.c` と一致。

| ポート | 方向 | 動作 |
|---|---|---|
| 10 (FDCD) | out | ドライブ選択。0→drivea.dsk、1→driveb.dsk。`io.DRIVE` 更新。 |
| 11 (FDCT) | out | track を保持。 |
| 12 (FDCS) | out | sector(1 起点)を保持。 |
| 13 (FDCOP)| out | **DMA トリガ**。値 0=read / 1=write。<br>linear = track×26 + (sector−1)。<br>disk[linear×128 : +128] ↔ mem[DMA_addr : +128]。同期(即完了)。<br>DMA_addr = (DMAH<<8) \| DMAL。 |
| 14 (FDCST)| in  | ステータス。範囲内アクセスなら 0(OK)、範囲外なら非0。 |
| 15 (DMAL) | out | DMA アドレス下位。 |
| 16 (DMAH) | out | DMA アドレス上位。 |

drivea.dsk はブート+カーネル(セクタ 0 = boot、セクタ 1〜 = kernel)。
driveb.dsk は FAT12 ボリューム。両方 `arch/z80pack/disks/` から読む。
write は **メモリ上のイメージにのみ反映**(既定。`--commit-disk` 指定時のみファイルへ書戻し)。

### タイマ(100Hz IM1 割込)

- `out (27), 1` … タイマ ON(`io.timer_on=1`)。
- `TIMER_AUTO=1` かつ `timer_on` のとき、各ステップで `CYCLES` を進め、
  `CYCLES - last_tick_cycles >= TIMER_PERIOD_CYCLES`(既定 40000 ≒ 4MHz/100Hz)
  ごとに `TICKS++` し `INT_PENDING=1`。
- 次ステップ冒頭で `INT_PENDING==1 && IFF1==1 && !HALTED` なら **IM1 割込を実行**:
  push PC / PC=0x0038 / IFF1=IFF2=0 / `INT_PENDING=0` / trace.log に `>>> INT (tick N)` 。
  HALTED 中に割込が来たら HALT 解除して PC+1 から。
- `IFF1==0` のときは割込を保留(INT_PENDING は立てたまま)。EI の 1 命令後に解禁
  (Z80 の EI 遅延を模す)。

`TIMER_PERIOD_CYCLES` と `TIMER_AUTO` は regs.txt(メタ)/io.json で調整。
バグ再現時は `TIMER_AUTO=0` にして、疑わしい命令の直前で `tz80 int` を撃つ。

## ブート手順

```
python3.11 python/tz80.py reset                    # drivea sec0 → 0x0000, PC=0
python3.11 python/tz80.py run --quiet --max 400000 # tizix が # プロンプトまで(~1.5s)
python3.11 python/tz80.py save at_prompt           # ここをショートカットに
```

boot.s が NSEC(254)セクタを drivea から 0x0100 へ read →`jp 0x0100`→ crt0.s
→ init → kernel_init(タイマ ON)→ sh → builtin_init(f_mount / vfs_init /
kload_driver)→ readline の `while(!PHYS_RXRDY())` スピンで入力待ち(0x78FC 付近)。

シェルにコマンドを送るには:
```
python3.11 python/tz80.py console in 'mkdir A\r'   # 入力キューに積む
python3.11 python/tz80.py run --quiet --max 300000 # コマンドが処理されるまで走らせる
```

## このバグを捕まえる手順(想定ワークフロー)

1. `reset` → `run --until 0x0100` → `save booted`。
2. `run --until <fat_mkdir か f_opendir の入口>` などで crash 手前まで。`save pre`。
3. ウォッチ設定: `watch add pc-range` / `watch add sp < 8C00` /
   `watch add mem 8400 85EE w` / `watch add opcode-illegal` / `watch add halt-with-di`。
4. `int auto off`。`step` で FatFs 処理を 1 命令ずつ進める。
5. 各命令の直後に `int`(ISR 手動注入)して `step`、ISR から戻ったら
   `step` を続け、**どの ISR タイミングで**どのメモリ/レジスタが化けるか観察。
   化けた瞬間 watch が停止させる。`stack` / `mem` で破壊箇所を確定。
6. 仮説(スタックオーバーフロー / ISR のレジスタ退避漏れ / cpmsim FDC)を切り分け。
   - スタック説: watch `sp < 8C00` が先に鳴るか。
   - ISR 退避漏れ説: ISR 前後で regs.txt を diff(全レジスタ + 裏レジスタ)。
   - FDC 説: `out (13)` の前後で mem を diff。DMA が想定外番地へ書いていないか。

## 実装メモ / 未決

- `z80` モジュールの単一ステップ API を要確認。無ければ「現命令をデコードして
  長さと分岐先(ret は [SP])を求め、全 next-PC 候補にブレークして 1 命令 run」で代替。
- レジスタの読み書き I/F(`m.pc` 等の属性 or `m.set_state()`)を要確認。
  無ければメモリ経由 or モジュール拡張。
- 逆アセンブラ: `z80` モジュールにあれば流用、無ければ最小限を自前(頻出命令のみ)。
- R レジスタ(リフレッシュ)は近似で可。バグ再現には影響しない見込み。
- `--commit-disk` 無しなら driveb.dsk への write はメモリ内イメージのみ(セッション内で完結)。
- パスは `python/tzpaths.py` に合わせて `arch/z80pack/disks/` を参照。
