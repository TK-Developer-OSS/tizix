# MEGA2560_68000_DTACK_TEST

Arduino Mega 2560 をホストマイコンとして使用し、Motorola 68000 (MC68000) CPU のバス制御、クロック供給、SRAM へのプログラム転送、仮想 UART (Serial) デバイス、およびハードウェア割り込み (IPL/IACK) をエミュレーション・制御する実験プロジェクトです。

下記サイトのようにuClinuxを動かすことをゴールにしている
https://kikb.web.fc2.com/mc68000/index.html

---

## 1. システム概要 & アーキテクチャ

* **CPU**: MC68000 (4MHz クロック: Mega2560 Timer1 OC1A=D11 から供給)
* **ホストマイコン**: Arduino Mega 2560 (16MHz, Serial 1,000,000 bps)
* **メモリ (SRAM)**: 16bit バス接続 SRAM
* **バス制御方式**:
  1. Mega2560 が CPU をリセット/HALT状態に保持したままバスを占有し、SRAM に ROM イメージを転送 & ベリファイ。
  2. 転送完了後、4MHz クロック起動 → バスを Hi-Z で開放 → `/HALT`, `/RESET` を解除して 68000 起動。
  3. CPU 走行中は Mega2560 がバスを監視し、`/DTACK` 信号のパルス生成、A20=1 空間の仮想 UART アクセス処理、Timer5 (1秒周期) によるハードウェア割り込み要求 (IPL/IACK) を処理。

## 3. メモリ & I/O マップ

### メモリ空間 (A20 = 0)
* `0x000000 - 0x0003FF`: 例外ベクタテーブル
  * `0x000000 - 0x000003`: 初期 SSP (`0x0000FF00`)
  * `0x000004 - 0x000007`: 初期 PC (`0x00000100`)
  * `0x000078 - 0x00007B`: 割り込みベクタ 30 (レベル 6 割り込みハンドラ `0x00000300`)
* `0x000100 - 0x00XXXX`: 実行コード領域 (ROM イメージロード先)
* `0x00F000`: ワーク用 tick カウンタ領域

### 仮想 I/O 空間 (A20 = 1)
* `0x1F0000` (奇数アドレス / LDS): **UART STATUS レジスタ** (Read)
  * bit0: `TXRDY` (送信可能)
  * bit1: `RXRDY` (受信データあり)
* `0x1F0002` (偶数アドレス / UDS): **UART DATA レジスタ** (Read/Write)
  * Write: Mega 2560 の Serial へ 1 バイト送信 (1Mbps)
  * Read: Mega 2560 の Serial バッファから 1 バイト取得

## 4. 割り込み処理方式 (Level 6 ベクタード割り込み)

1. Mega2560 の `Timer5` (1 秒周期 CTC) により `g_irq_req = 1` がセットされる。
2. `loop()` 内で検出後、`IPL_LV6()` により IPL2..0 に `001` (負論理: IPL0=H, IPL1=L, IPL2=L) を出力。
3. 68000 が割り込みを受理し、IACK サイクル (FC0..2 = 111) を発行。
4. Mega2560 が IACK サイクルを検出し、IPL を平常 (`111`) に戻す。
5. データバス `D0-D7` (PORTF) にベクタ番号 `30` (`0x1E`) を載せ、`/DTACK` パルスを出力して応答。
6. 68000 がベクタ 30 のアドレス (`0x78`) からハンドラ番地 (`0x00000300`) をフェッチしてハンドラを実行、`RTE` で復帰。

## 6. 引継ぎ事項・注意事項

1. **シリアルモニタ設定**:
   * ボーレートは **1,000,000 bps (1Mbps)** です。TeraTerm 等の端末ソフトでも 1Mbps に設定してください。
2. **/DTACK 応答タイミング**:
   * Mega2560 によるソフトウェア `/DTACK` パルス制御を行っているため、`__asm__ __volatile__ ("nop");` のパルス幅調整がクリティカルです。
3. **/VPA と /DTACK の併用禁止**:
   * 割り込み応答時はベクタード応答 (`/DTACK` + データバスにベクタ番号) を使用します。`/VPA` (オートベクタ) と `/DTACK` を同時にアサートするとバス競合・CPU 停止の原因になります。
4. **SRAM 整定待ち時間**:
   * `sram_read()` ではデータ整定のため `delayMicroseconds(3);` を設けています。

* **担当 / 目的**: A20・/UDS・/LDS で上下バイトを分離アクセスする回路改修後、68000 が
  走らなくなった件の原因究明。CPU を抜き、Mega + SRAM ボードだけで検証する。
* **変更点**:
  - `MEGA2560_68000_DTACK_TEST.ino`: 中身を **BUSPROBE**(PC からコマンドで叩く
    バス代行プローブ)に差し替え。直前の SIGNAL_TOGGLE_TEST は

    幅でステップ番号が読める)。どちらも頭に /AS=H の目印を入れる。
  - 注意: シリアルを開いても Mega はリセットされない(状態が残る)。開いた瞬間に
    NUL が 1 バイト来るのでファーム側で制御文字を捨てている。PC 側クライアントは

        いた。OR の CE ではありえないので、プローブ位置か素子の取り違えが疑わしい。
        → `sc` で取り直し中。U7 は 74HC32(回路図の「32やめて00」は前構成の残骸)。

  - `tizix.ps1`: 新規。シリアルクライアント(2026-09-21 に 1Mbps → 115200 bps へ変更。TeraTerm が化けたため)。`.\tizix.ps1 -Seconds 10`、`-Send "pwd`r"`、`-Log <file>`。
* **検証結果・ステータス**: **成功**。
  `tizix` バナー → `FAT Drive FAILED (continuing)` → `[/root]#` プロンプト。
  pwd / ps / cd が動作。SRAM 転送 11810 ワード verify NG=0、バイトレーン verify も UDS/LDS とも NG=0。
* **ハマりどころ(全部 Mega 側。SRAM も 68000 も無罪だった)**:
  1. SRAM 書込で **/UDS,/LDS を駆動していなかった**(CE#=A20|DS なので SRAM が選択されない)。
  2. 走行中の 68000 を載せたまま Mega だけ再起動すると、**クロックが止まった CPU がバスを掴んだまま**で転送全滅。
     リセット中に 20ms クロックを与えて手放させる。
  3. **/AS を見た瞬間に DS を読むのは早すぎる**(/AS=S2, DS=S4)。UART の DATA と STATUS が入れ替わる。
  4. **/DTACK を「/AS が戻るまで保持」にすると次サイクルを巻き込む** → 固定幅パルス(8 nop)へ。
  5. **「/AS が H に戻るのを待つ」のも破綻**。窓が 250ns しかなく一度逃すとずれ続け、1 サイクル 0.7ms まで低下。
     → 観測せず固定 2us 待ち。
  6. **DTACK パルス中の割り込みでパルスが伸び 1 文字消える** → cli/sei でアトミック化。
* **次(M2)**: SD カードモジュールを SPI(D50-53)に接続し、Mega 側で plat.h の SD_* プロトコルを実装する。
  現状は STATUS に常時 `ERROR|DATA_RDY` を返すスタブ(これが無いと FatFs が無限待ちして起動時に無言ハングする)。
